HAL RTC migration: List of applicable concepts ¶

This section provides information about the HAL RTC applicable architecture concepts.

List of specific concepts ¶

Concept

Description

Split legacy HAL_PPP_Init into Init (build handle object) and config (apply configuration)

Remove the init and deinit functions and create a configuration function.

Remove Init structure from handle and convert Init structure into configuration one

Remove the Hal RTC handle.

Rename unitary init structures

Rename calendar and prescalers configuration structures.

Remove MspInit and MspDeInit callbacks

hal_rtc_MspInit and hal_rtc_MspDeInit are no longer available they are replaced by a user sequence to initializes and configures the RTC

Add unitary configuration APIs

Split calendar and prescalers APIs(configuration, structures and functions)

Split Global Register callback API to one register API per callback and remove unregister callback API

Remove callback registration function as there is no more Hal RTC handle.

The HAL RTC in hAL2 use exclusively weak callbacks.

HAL implementation relies on LL inline functions instead of direct register access.

HAL RTC APIs call LL APIs instead of registers access.

HAL defines and enum(those used for HW registers) are redirected to the equivalent LL ones.

HAL RTC defines and enumeration are based on LL define.

All public macros related to hardware (HW) are removed, and equivalent services added to the LL layer.

All hardware macros have been removed from the HAL RTC driver, and equivalent services are ensured through the LL APIs.

Remove single or double underscore prefixes from any define or macro, as this is not allowed per the C standard.

All underscore prefixes in RTC are removed.

Replace the “TypeDef” part of every typedef with “_t”.

All TypeDef part in RTC are replaced by _t

Replace big macros with inline functions for consistency.

Using inline functions instead of large macros for the RTC helps maintain code consistency, improve readability, and benefit from compiler optimizations. Inline functions also offer better support for debugging and strict type management, thereby reducing the risk of errors.

Replace non-modifiable pointers with const keywords.

Adding const keywords to non-modifiable pointers ensures that either the pointer itself or the data it points to cannot be modified. This enhances code safety and readability and using const, you prevent unintended modifications and make your code more robust and maintainable.

Merge HAL extension files with common ones and remove the EX prefix from APIs.

Only one HAL RTC header file now is available and all the macro,define,function ,… in hal_rtc_ex.h are adapted and mergerd in hal_rtc.h

Remove stm32tnxx_ll_ppp.c files

The LL source file is removed.

Split Peripheral Configuration from Start in System HAL Drivers.

In RTC driver alarm and wakeup features are now split between configuration functions and start functions .

Replace Finite Parameter Defines (Including PPP Instances) with Enum Types at HAL Levels.

Convert finite parameters, (including RTC instances) into enumerated types (enums) at the HAL level. This improves code readability, maintainability, and type safety.

Keep Global HAL PPP IRQ Handler and Provide Specialized HAL PPP IRQ Handlers for Individual scope

HAL_RTC_IRQHandler still available and we found also four new IRQ handler

  1. HAL_RTC_ALARM_IRQHandler() specific to RTC Alarm.

  2. HAL_RTC_TIMESTAMP_IRQHandler() specific to RTC TimeStamp.

  3. HAL_RTC_WAKEUP_IRQHandler() specific to RTC Wakeup.

  4. HAL_RTC_SubSecondsUnderflow_IRQHandler() specific to RTC SubSecondsUnderflow.

Other HAL RTC changes ¶

Concept

Consideration

Split HAL RTC driver

Create two separate HAL RTC & HAL TAMP drivers mirroring the reference manual

Remove HAL handle from HAL RTC & TAMP drivers

No more handle in hal2 for both RTC and TAMP drivers.

Change write protection usage

Create APIs to lock and unlock the write protection for the usersthat need to used before setting the date and time.

Note: The date and time setting register no longer automatically unlocks the write protection.

  • HAL_RTC_EnableWriteProtection()

  • HAL_RTC_DisableWriteProtection()

Add GetDateTime API

Add a function to retrieve the date and the time.

  • HAL_RTC_CALENDAR_GetDateTime()

Align the structures and naming convention with POSIX

Use standard naming sec, min, hour instead of full names.

  • Hours -> hour

  • Minutes -> min

  • Seconds -> sec

Factorize Alarm code

Update the alarm functionality to allow the user to select the specific alarm for each desired operation.

  • HAL_RTC_ALARM_A

  • HAL_RTC_ALARM_B
