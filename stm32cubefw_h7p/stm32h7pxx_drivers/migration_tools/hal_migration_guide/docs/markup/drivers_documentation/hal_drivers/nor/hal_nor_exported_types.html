HAL NOR Types migration ¶

This section provides information about the HAL NOR types migration.

Note

Most of APIs are split according to the command set of the device.

See HAL NOR Typical use cases for migration .

Note

  • HAL_NOR_STATE_BUSY is split to :

    • HAL_NOR_STATE_PROGRAM_ACTIVE for program API.

    • HAL_NOR_STATE_ERASE_ACTIVE for Erase API.

    • HAL_NOR_STATE_READ_ACTIVE for Read API.

  • HAL_NOR_STATE_ERROR is replaced with HAL_NOR_STATE_FAULT .

  • HAL_NOR_STATE_PROTECTED is removed , no more state to reflect the NOR write protection instead use the function HAL_NOR_IsEnabledWriteProtection to know if the NOR is write protected.

  • HAL_NOR_STATE_READY is replaced with HAL_NOR_STATE_IDLE .

  • Related concepts: Revise and optimize the HAL state machine.

HAL1

Memory Timeout status

Removed : Timeout status is removed as NOR memory itself does not signal a timeout,

timeout are now managed in the process APIs by returning HAL_TIMEOUT ,

when the on-going status exceeds a predefined duration.
