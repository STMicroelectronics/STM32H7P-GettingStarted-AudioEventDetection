HAL SMBUS migration: List of applicable concepts ¶

This section provides information about the HAL SMBUS applicable architecture concepts.

Concepts for SMBUS ¶

Concept

Description

Split legacy HAL_PPP_Init into Init (build handle object) and config (apply configuration)

Split the initialization function of the HAL SMBUS into two separate functions:

  • HAL_SMBUS_Init : This function is responsible for creating and setting up the handle object.

  • HAL_SMBUS_SetConfig : It sets parameters such as clock speed, addressing mode, and other operational settings.

Remove Init structure from handle and convert Init structure into configuration one

The init structure is removed and moved into hal_smbus_config_t configuration structure.

Rename handle structure

The handle structure is renamed to hal_smbus_handle_t .

Rename unitary init structures

The structure SMBUS_InitTypeDef no longer available they are replaced par hal_smbus_config_t .

Remove MspInit and MspDeInit callbacks

HAL_SMBUS_MspInit and HAL_SMBUS_MspDeInit are no longer available they are replaced by a user sequence to initializes and configures the SMBUS.

Add unitary configuration APIs

New APIs are available to get and set SMBUS features.

Add HAL User Data Set/Get APIs

Two function to Set/Get User Data are available HAL_SMBUS_SetUserData and HAL_SMBUS_GetUserData .

Split Global Register callback API to one register API per callback and remove unregister callback API

The callback registration is handled by specific functions for each SMBUS event.

HAL implementation relies on LL inline functions instead of direct register access.

HAL SMBUS APIs call LL APIs instead of registers access. For example : LL_I2C_EnableSlaveByteControl() , LL_I2C_AcknowledgeEnable() in the HAL direct transfer configuration function.

HAL defines and enum(those used for HW registers) are redirected to the equivalent LL ones.

HAL SMBUS defines and enumeration are based on LL define. For example : the HAL constant HAL_SMBUS_PERIPHERAL_MODE_HOST is based on the LL constant LL_I2C_MODE_SMBUS_HOST .

All public macros related to hardware (HW) are removed, and equivalent services added to the LL layer.

ALL public macros in the HAL for accessing SMBUS registers have been removed. Instead, the LL (Low Layer) APIs now offer equivalent functionality, providing efficient and direct access to SMBUS registers.

Revise and optimize the HAL state machine.

The SMBUS state machine is reworked to ensure transitions of the peripheral functional states

Revise and optimize the status return of HAL APIs.

Update SMBUS function to return HAL_INVALID_PARAM in case of NULL p_config structure pointer HAL_ERROR in case of error , HAL_TIMEOUT in case of user timeout , HAL_BUSY in case of process ongoing and HAL_OK in case of operation completed successfully.

Revise and optimize HAL error management.

Involves redesigning the error handling mechanisms within the HAL to improve the detection, reporting, and handling of errors.

Remove single or double underscore prefixes from any define or macro, as this is not allowed per the C standard.

All underscore prefixes in SMBUS are removed .

Replace the “TypeDef” part of every typedef with “_t”.

All TypeDef part in SMBUS are removed and replaced by _t .

Replace big macros with inline functions for consistency.

Using inline functions instead of large macros for the SMBUS helps maintain code consistency, improve readability, and benefit from compiler optimizations. Inline functions also offer better support for debugging and strict type management, there by reducing the risk of errors.

Replace non-modifiable pointers with const keywords.

Adding const keywords to non-modifiable pointers ensures that either the pointer itself or the data it points to cannot be modified. This enhances code safety and readability and using const, you prevent unintended modifications and make your code more robust and maintainable.

Replace parameter and state checks with assertions.

The parameters and state are checked using ASSERT_DBG_STATE and ASSERT_DBG_PARAM macro .

Merge HAL extension files with common ones and remove the EX prefix from APIs.

Only one HAL SMBUS header file now is available and all the macro, define, functions,… in hal_smbus_ex.h are adapted and mergerd in hal_smbus.h .

Provide RTOS-compatible acquire/release bus services for communication peripheral drivers.

Implementing functions to manage the access to communication buses like SMBUS in a multi-tasking environment. These services ensure that only one task can use the bus at a time, preventing conflicts and ensuring data integrity. The acquire function locks the bus for a task, while the release function unlocks it, allowing other tasks to use the bus.

Replace Finite Parameter Defines (Including PPP Instances) with Enum Types at HAL Levels.

Convert finite parameters, (including SMBUS instances) into enumerated types (enums) at the HAL level. This improves code readability, maintainability, and type safety.

Add HAL_PPP Prefix to All HAL Peripheral APIs (Defines, Macros, Types, and Functions).

All HAL SMBUS functions start with HAL_SMBUS . All HAL SMBUS enum and struct start with hal_smbus .

Other HAL SMBUS changes ¶

Concept

Consideration

Provide APIs for timeout configuration

Add (STM32_UTILS_I2C_SMBUS_ComputeTimeoutA() / STM32_UTILS_I2C_SMBUS_ComputeTimeoutB())APIs in the helper files utils_i2c.c / .h to calculate the timeout value based on the RCC clock speed.

Provide APIs for timing calculation

Add (STM32_UTILS_I2C_ComputeAdvanced() / STM32_UTILS_I2C_ComputeTimingBasic()) APIs in the helper files utils_i2c.c / .h to calculate the timing value using the shared formula with I2C.
