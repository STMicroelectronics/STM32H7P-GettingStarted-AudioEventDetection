HAL RNG Migration: List of Applicable Concepts ¶

This section provides information about the HAL RNG applicable architecture concepts.

Concepts for RNG ¶

Concept

Description

Split legacy HAL_PPP_Init into Init (build handle object) and config (apply configuration)

The initialization has been split into separate init and config functions:

  • HAL_RNG_Init : Initializes the handle and link it to a RNG instance.

  • HAL_RNG_SetConfig : It sets parameters, such as RNG health test, clock divider, and other operational settings.

Remove Init structure from handle and convert Init structure into configuration one

The init structure is removed and moved into hal_rng_config_t configuration structure.

Rename handle structure

The handle structure is renamed to hal_rng_handle_t .

Remove MspInit and MspDeInit callbacks

HAL_RNG_MspInit and HAL_RNG_MspDeInit are no longer available they are replaced by a user sequence to initializes and configures the RNG.

Add unitary configuration APIs

New APIs are available to Get and set RNG features.

Split Global Register callback API to one register API per callback and remove unregister callback API

The callback registration is handled by specific functions for each RNG event.

HAL implementation relies on LL inline functions instead of direct register access.

HAL RNG APIs call LL APIs instead of registers access.

HAL defines and enum(those used for HW registers) are redirected to the equivalent LL ones.

HAL RNG defines and enumeration are based on LL define.

All public macros related to hardware (HW) are removed, and equivalent services added to the LL layer.

All hardware macros have been removed from the HAL RNG driver, and equivalent services are ensured through the LL APIs.

Revise and optimize the HAL state machine.

The RNG state machine is reworked to ensure transitions of the peripheral functional states.

Revise and optimize the status return of HAL APIs.

Update RNG function to return HAL_INVALID_PARAM in case of NULL p_config structure pointer, HAL_ERROR in case of error, HAL_TIMEOUT in case of user timeout, HAL_BUSY in case of process ongoing, and HAL_OK in case of operation completed successfully.

Revise and optimize HAL error management.

Reduced the number of error codes to focus on the most critical errors, specifically HAL_RNG_ERROR_NONE , HAL_RNG_ERROR_SEED , and HAL_RNG_ERROR_CLOCK .

Remove single or double underscore prefixes from any define or macro, as this is not allowed per the C standard.

All underscore prefixes in RNG are removed.

Replace the “TypeDef” part of every typedef with “_t”.

All TypeDef part in RNG are removed and replaced by _t .

Replace big macros with inline functions for consistency.

Using inline functions instead of large macros for the RNG helps maintain code consistency, improve readability, and benefit from compiler optimizations. Inline functions also offer better support for debugging and strict type management, thereby reducing the risk of errors.

Replace non-modifiable pointers with const keywords.

Adding const keywords to non-modifiable pointers ensures that either the pointer itself or the data it points to cannot be modified. This enhances code safety and readability and using const, you prevent unintended modifications and make your code more robust and maintainable.

Replace parameter and state checks with assertions.

The parameters and state are checked using ASSERT_DBG_STATE and ASSERT_DBG_PARAM macro.

Merge HAL extension files with common ones and remove the EX prefix from APIs.

Only one HAL RNG header file now is available and all the macro, define, functions,… in hal_rng_ex.h are adapted and mergerd in hal_rng.h .

Remove stm32tnxx_ll_ppp.c files

No stm32tnxx_ll_rng.c files in HAL2.

Replace Finite Parameter Defines (Including PPP Instances) with Enum Types at HAL Levels.

Convert finite parameters, (including RNG instances) into enumerated types (enums) at the HAL level. This improves code readability, maintainability, and type safety.

Add HAL_PPP Prefix to All HAL Peripheral APIs (Defines, Macros, Types, and Functions).

All HAL RNG functions start with HAL_RNG . All HAL RNG enum and struct start with hal_rng .

Other HAL RNG Changes ¶

Concept

Consideration

Rework process APIs concept to support all RNG IP version.

The philosophy is to offer a set of APIs which allow the user to:
  • In polling mode:

    • HAL_RNG_Generate_RandomNumber() : to generate N random number word. The process generation is limited by a user timeout.

  • In interrupt mode:

    • HAL_RNG_GenerateRandomNumber_IT() to generate N random number word.

    • HAL_RNG_IRQHandler() to handle occurred interrupts and will call HAL_RNG_GenerationCpltCallback() when the generation has completed.

Provide ready to use APIs which contain specific configuration.

Three functions :

1 : Candidate German BSI standard configuration function: HAL_RNG_SetCandidateGermanBSIConfig() .

2 : NIST standard configuration function: HAL_RNG_SetCertifiedNISTConfig() flagged with RNG_CERT_NIST .

3 : Candidate NIST configuration function: HAL_RNG_SetCandidateNISTConfig() .

Remove recovery mechanism from get random number API.

It’s up to user to recover any seed error through the HAL_RNG_RecoverSeedError() as:

  • Recovery is not always granted.

  • Provide flexibility of recovery mechanism within an application.

  • Recovery mechanism can be called within error callback to be based on static timing not systick.

  • When recovery ensured use can call again the polling or IT API to generate again.
