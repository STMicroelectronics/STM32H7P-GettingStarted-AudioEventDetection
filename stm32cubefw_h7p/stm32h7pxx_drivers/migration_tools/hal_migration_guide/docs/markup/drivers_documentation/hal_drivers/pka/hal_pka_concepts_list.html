HAL PKA migration: List of applicable concepts ¶

This section provides information about the HAL PKA applicable architecture concepts.

Concepts for PKA ¶

Concept

Description

Split legacy HAL_PPP_Init into Init (build handle object) and config (apply configuration)

Provide a separate configuration per operating mode with the parameters strictly required for the given mode.

Rename handle structure

The handle structure is renamed to hal_pka_handle_t .

Remove MspInit and MspDeInit callbacks

HAL_PKA_MspInit and HAL_PKA_MspDeInit are no longer available they are replaced by a user sequence to initializes and configures the PKA.

Add HAL User Data Set/Get APIs

Two function to Set/Get user data are available HAL_PKA_SetUserData() and HAL_PKA_GetUserData() .

Split Global Register callback API to one register API per callback and remove unregister callback API

The callback registration is handled by specific functions for each PKA event.

HAL implementation relies on LL inline functions instead of direct register access.

HAL PKA APIs call LL APIs instead of direct register access. For example : LL_PKA_SetMode and LL_PKA_Enable in the HAL_PKA_ECC_SetConfigPointCheck configuration function.

HAL defines and enum(those used for HW registers) are redirected to the equivalent LL ones.

HAL PKA defines and enumerations are based on LL defines. For example : the HAL constant HAL_PKA_ERROR_ADDRERR is based on the LL constant LL_PKA_FLAG_ADDRERR .

All public macros related to hardware (HW) are removed, and equivalent services added to the LL layer.

All hardware macros have been removed from the HAL PKA driver, and equivalent services are ensured through the LL APIs.

Revise and optimize the HAL state machine.

The PKA state machine is reworked to ensure transitions of the peripheral functional states.

Revise and optimize the status return of HAL APIs.

Update PKA function to return HAL_INVALID_PARAM in case of NULL p_config structure pointer HAL_ERROR in case of error , HAL_TIMEOUT in case of user timeout , HAL_BUSY in case of process ongoing and HAL_OK in case of operation completed successfully.

Revise and optimize HAL error management.

Involves redesigning the error handling mechanisms within the HAL to improve the detection, reporting, and handling of errors.

Remove single or double underscore prefixes from any define or macro, as this is not allowed per the C standard.

All underscore prefixes in PKA are removed.

Replace the “TypeDef” part of every typedef with “_t”.

All TypeDef part in PKA are removed and replaced by _t .

Replace non-modifiable pointers with const keywords.

Adding const keywords to non-modifiable pointers ensures that either the pointer itself or the data it points to cannot be modified. This enhances code safety and readability and using const, you prevent unintended modifications and make your code more robust and maintainable.

Replace parameter and state checks with assertions.

The parameters and state are checked using ASSERT_DBG_STATE and ASSERT_DBG_PARAM macro .

Remove stm32tnxx_ll_ppp.c files

The source file stm32_ll_pka.c is removed in HAL2 .

Replace Finite Parameter Defines (Including PPP Instances) with Enum Types at HAL Levels.

Convert finite parameters, (including PKA instances) into enumerated types (enums) at the HAL level. This improves code readability, maintainability, and type safety.

Optimize HAL PPP IRQ Handlers by Reordering Processes and Error Management Statements to Prioritize Critical Interrupts

In HAL2, the implementation of HAL_PKA_IRQHandler API has been improved to prioritize the handling of critical interrupts.

Add HAL_PPP Prefix to All HAL Peripheral APIs (Defines, Macros, Types, and Functions).

All HAL PKA functions start with HAL_PKA . All HAL PKA enum and struct start with hal_pka .

Other HAL PKA changes ¶

Concept

Consideration

Unknown result size.

The following functions do not return the correct length:

HAL_PKA_ModExp_GetResult() , HAL_PKA_ECDSASign_GetResult() , HAL_PKA_ECCMul_GetResult() .

Split operation process from operation configuration.

For each compute operation provide a dedicated configuration API and provide one single compute API to be used of all operation.
