This section provides information about the HAL SMARTCARD types migration.

Note

The callback registration in HAL2 is handled by specific functions for each SMARTCARD event. See Register Callbacks for more details.

HAL_SMARTCARD_MSPINIT_CB_ID and HAL_SMARTCARD_MSPDEINIT_CB_ID are removed because the functions HAL_SMARTCARD_MspInit() and HAL_SMARTCARD_MspDeInit() are removed.

Related concept : Split Global Register callback API to one register API per callback and remove unregister callback API

Related concept : Remove MspInit and MspDeInit callbacks

HAL SMARTCARD state definition ¶

In HAL2, key changes include:

  1. Renaming of several states.

  2. Removal of states HAL_SMARTCARD_STATE_TIMEOUT and HAL_SMARTCARD_STATE_ERROR .

  3. Adding a new state HAL_SMARTCARD_STATE_ABORT

HAL SMARTCARD advanced feature initialization structure ¶

HAL1

HAL2 

typedef struct
{
    uint32_t AdvFeatureInit;
    uint32_t TxPinLevelInvert;
    uint32_t RxPinLevelInvert;
    uint32_t DataInvert;
    uint32_t Swap;
    uint32_t OverrunDisable;
    uint32_t DMADisableonRxError;
    uint32_t MSBFirst;
    uint16_t TxCompletionIndication;
} SMARTCARD_AdvFeatureInitTypeDef;

This structure has been removed, along with its association as a member of the handle.

Each advanced feature is now configured and controlled through specific functions, allowing direct management of these features without relying on the previous structure.

For more information on enabling or disabling advanced features, see the section HAL SMARTCARD advanced features for more details on advanced feature management functions.
