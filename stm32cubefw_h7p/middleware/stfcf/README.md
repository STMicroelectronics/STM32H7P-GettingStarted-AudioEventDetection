# __Middleware: *stfcf*__

This package is the STM32 Flexible Crypto Framework (STFCF) middleware provided by STMicroelectronics.

## __1. Abstract__


The STM32 Flexible Crypto Framework is designed to provide an easy access to the cryptographic offer by STMicroelectronics.


## __2. Package structure overview__

This middleware is an ecosystem to experiment with several paths and to provide cryptographic services (with multiple implementations) from the Platform Security Architecture (PSA) Application Programming Interface (API).

The same API calls for many cryptographic engines:

  * Alternative thanks to Hardware acceleration with HAL API, called "Mbed TLS Alt HAL"
  * Alternative thanks to STCryptoLib, called "Mbed TLS Alt STCryptoLib"
  * MbedTLS
  * PSA driver Key Wrap Engine, called "KWE"
  * Alternative third-party called "Mbed TLS custom alternative"

They are selectable by configuration only.

### __2.1. High-level API__

The high level interface is the PSA API. It binds directly to the PSA API of Mbed TLS middleware.

The cryptography library in Mbed TLS is a reference implementation of the cryptography interface of the PSA.

  * __Standardized PSA API__ that manages crypto and key operations.

 This API is used for many reasons:

   * It is used to import a key in transparent mode.
   * It is used to store keys in persistent memory.
   * It is used to manipulate opaque keys by identifiers.
   * It is used to access one or several crypto drivers.

> **_NOTE:_**  PSA Cryptography API is a standard by Arm. See [Platform Security Architecture](https://arm-software.github.io/psa-api/).


### __2.2. Internal structure__

The STM32 Flexible Crypto Framework is proposed with the following configuration paths (promotion by order):

  * Mbed TLS Alt by HAL: HAL implementation, silicon first
  * Mbed TLS Alt by STCryptoLib: STCryptoLib implementation for software optimization
  * Mbed TLS implementation directly: Mbed TLS implementation, the default case
  * PSA driver KWE: Key Wrap Engine based on CCB peripheral driver, as option
  * Mbed TLS custom alternative: custom case implementation

## __3. Configuration__

STM32 Flexible Crypto Framework is delivered with a template (`mx_stfcf_config.h` file) listing all available options.

This template can be used directly or generated by the STM32CubeMX2.

Three levels of configurations are possible:
* __Main configuration__ (ready-to-use combinations): Allow to combine ready to use configuration with different
engine per family of algorithm
* __Advanced configuration__ (manual mode): All options are displayed to keep the control and setup customized
configuration with tools helper

As a beginner, the user can use the predefined configurations and combined them.
As an expert, the user can customize a new configuration under their control.

Whatever the level, files are generated (`mx_stfcf_config.h`, `mx_mbedtls_config.h`, and `mx_mbedtls_alt_config.h` files by default) is installed at
application user space.
