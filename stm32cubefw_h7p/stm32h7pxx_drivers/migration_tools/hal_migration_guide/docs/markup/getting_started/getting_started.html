Getting started ¶

The Migration material ¶

To accelerate the HAL1 to HAL2 migration journey for a given application, the following materials and tools are provided:

  • HAL1 automatic detection script: ( HAL1 automatic detection script )

    • Scan Application Files: The script scans the user’s application files and detects all encountered HAL1 APIs, including defines, types, functions, and macros.

    • Log and Report: The script logs and reports each detected HAL1 API, providing the corresponding section in the HAL1 to HAL2 migration documentation. This documentation explains how to perform the migration of each given API according to its usage and scenario.

  • HAL1 to HAL2 migration user guide: ( HAL1 to HAL2 details )

    • HAL2 Architecture Concepts: Documentation explaining the architectural concepts behind the changes from HAL1 to HAL2.

    • Driver-Specific Migration Rules: For each HAL and LL driver, an exhaustive listing of HAL1 APIs is provided, along with the required rules to successfully migrate them to HAL2.

      The documents also provide a set of code snippets showing how to transition from HAL1 to HAL2. Users can copy these code snippets to their target application, facilitating a rapid and efficient HAL1 to HAL2 migration.

    • Concrete Applicative Use Cases: For each HAL or LL driver, a set of concrete applicative use cases is described, providing the equivalency between HAL1 and HAL2 APIs with appropriate explanations.

  • Migration example: ( Migration example )

    • A step-by-step example to migrate a real project from using HAL1 drivers to using HAL2 drivers.

    • Demonstrating how to use the migration material in practice.

    • Including the necessary IDE settings updates and the usage of STM32CubeMX2 to accelerate the IDE settings update and the HAL drivers initialization sequences migration.

  • HAL migration checklist ( link ): Enabling users to monitor their progress and ensure that all steps of the migration journey are completed successfully.

Note

STM32CubeMX2 usage for initialization sequences and IDE project settings:

  • For applicative code sequences related to initialization, STM32CubeMX2 is used in the recommended migration journey. It directly generates the required HAL2 initialization sequences, including the target peripherals as well as the Clock, NVIC, and GPIO services needed by these peripherals. STM32CubeMX2 is also used as a reference for HAL to HAL2 changes that need to be made on the IDE side, such as include paths, pre-processor settings, etc.

The Migration journey ¶

The recommended migration journey involves the various migration materials in the below sequence to leverage HAL1 to HAL2 user application migration.

Initially, duplicate your project and replace the HAL1 driver with the equivalent HAL2 driver. Within the IDE settings, select the target device, update the linker and startup files, and update the inclusion path to accommodate the HAL2 driver location. Finally, in the IDE, invoke the HAL2 source files instead of the HAL1 files and update the pre-processor defines according to the HAL2 requirements.

Once the IDE settings are updated, use the automatic HAL1 APIs detection script to identify and report all HAL1 references in the application code. The script logs and reports each detected API, and provides the corresponding section in the HAL1 to HAL2 migration documentation. Additionally, the script includes a stubbing feature that allows you to delimit the encountered HAL1 APIs in the application code using a dedicated compilation define. This enables the application to compile without errors, facilitating a smoother and more controlled migration process.

Go through the logging report and, for each reported API, use the migration documentation and follow the instructions to resolve HAL1 references. This may require loops. Additionally, STM32CubeMX2 is used to generate initialization sequences, including system clock, NVIC, and GPIO services needed by the peripherals.

To accelerate the IDE project updates and the migration of the applicative code related to the HAL2 initialization sequence, use STM32CubeMX2 to generate a new project with IDE settings, linker, startup files, selected HAL driver files, and initialization source code for the given peripherals. The outputs of this STM32CubeMX2 project can be utilized to easily update the various IDE settings, the hal conf header file, and the initialization source code of the project to be migrated.

Note

For more information on the STM32Cube HAL2 version, refer to the STM32Cube HAL2 User Manual .
