HAL SRAM migration: List of applicable concepts ¶

This section provides information about the HAL SRAM applicable architecture concepts.

Concepts for SRAM ¶

Concept

Description

Split legacy HAL_PPP_Init into Init (build handle object) and config (apply configuration)

The HAL_SRAM_Init() has been split to:

  • HAL_SRAM_Init() to initialize the SRAM handle and associates an instance.

  • HAL_SRAM_SetConfig() to configure the FMC peripheral.

  • HAL_SRAM_SetConfigxxxMemory() to configure the memories with different access mode.

  • HAL_SRAM_EnableMemory() to enable the corresponding SRAM device.

Remove Init structure from handle and convert Init structure into configuration one

The init structure NORSRAM_InitTypeDef is removed from the handle and converted into:

  • hal_sram_config_t static configuration.

  • hal_sram_xxx_memory_config_t one of the four memory-specific.

Rename handle structure

The handle structure SRAM_HandleTypeDef is renamed to

  • hal_sram_handle_t .

Rename unitary init structures

The structure NORSRAM_InitTypeDef is no longer available, It is replaced with:

  • hal_sram_config_t .

  • hal_sram_xxx_timings_config_t .

  • hal_sram_xxx_memory_config_t .

Remove MspInit and MspDeInit callbacks

The HAL_SRAM_MspInit() and HAL_SRAM_MspDeInit() are no longer available, they are replaced by a user sequence to initializes and configures the SRAM.

Add HAL User Data Set/Get APIs

The functions to Set/Get User Data are available:

  • HAL_SRAM_SetUserData()

  • HAL_SRAM_GetUserData() .

Revise and optimize the HAL state machine.

The SRAM state machine is reworked:

  • removing the protected state HAL_SRAM_STATE_PROTECTED .

  • adding configured states HAL_SRAM_STATE_CONFIGURED and HAL_SRAM_STATE_MEMORY_CONFIGURED .

Revise and optimize the status return of HAL APIs.

The input parameter checks using assertions have been added to the APIs.

Remove single or double underscore prefixes from any define or macro, as this is not allowed per the C standard.

All underscore prefixes in SRAM are removed.

Replace the “TypeDef” part of every typedef with “_t”.

All TypeDef part in SRAM are replaced by _t .

Replace non-modifiable pointers with const keywords.

The keyword const is added to non-modifiable pointers to ensure that neither the pointer itself nor the data it points to cannot be modified.

Replace parameter and state checks with assertions.

The parameters and state are checked using ASSERT_DBG_STATE and ASSERT_DBG_PARAM macros.

Rename LL core drivers to stm32_ppp_core.h/.c to avoid confusion with user LL drivers.

The core driver name is changed from stm32_ll_ppp.h/.c to stm32_ppp_core.h/.c ( stm32_fmc_core.h/.c ).

Add HAL PPP Services for Drivers with Handle to Retrieve Corresponding Peripheral Clock Frequency.

The HAL SRAM driver provides a new API to retrieve the clock frequency: HAL_SRAM_GetClockFreq() .

Replace Finite Parameter Defines (Including PPP Instances) with Enum Types at HAL Levels.

The finite parameters (including SRAM instances) are converted into enumerated types (enums) at the HAL level.

Replace the assert_param macro with ASSERT_DBG_PARAM, controlled by the USE_ASSERT_DBG_PARAM conditional.

The conditional compilation flag USE_ASSERT_DBG_PARAM is introduced to enable or disable debug parameter assertions.

Add ASSERT_DBG_STATE macro controlled by USE_ASSERT_DBG_STATE conditional.

The conditional compilation flag USE_ASSERT_DBG_STATE is introduced to enable or disable debug parameter assertions.

Other HAL SRAM changes ¶

Concept

Consideration

Use the sub-bank as the unitary instance instead of providing the base address and the bank offset

The new enumeration hal_sram_t has been added to select one of the four sub-banks of bank1 ( HAL_SRAM1 , HAL_SRAM2 , HAL_SRAM3 , HAL_SRAM4 ) as SRAM instance with no bank selection.

Split the configuration into Static configuration structure and Memory configuration structures

The HAL_SRAM_SetConfig() is called, then configure the memory HAL_SRAM_SetConfigxxxMemory() , and optionally HAL_SRAM_SetWrAsyncTimings() before use:

  • hal_sram_config_t configures static FMC parameters.

  • hal_sram_xxx_memory_config_t sets memory-specifics and the timings.

  • hal_sram_wr_async_timings_t is used if write async timings differ.

Add SRAM write protection state in the handle

The hal_sram_wr_protection_status_t is added in the handle to check the write protection status:

  • HAL_SRAM_WR_NOT_PROTECTED .

  • HAL_SRAM_WR_PROTECTED .

Remove WriteOperation from SRAM configuration structure

When needed the user call directly the corresponding API. The WriteOperation is removed from configuration, the write protection is enabled by default.

Remove process APIs as they depends of user application

There is no specific FMC hardware configuration needed for DMA requests, as read and write operations are directly accessible by the user.

Add API to check the status of write protection

  • HAL_SRAM_IsEnabledWriteProtection() to check the protection state.

Change timing parameters unit from cycle to ns

The static API is added to convert these values before setting them in the FMC register.

Remove __HAL_LINKDMA generic macro

DMA functionality is separated from SRAM because the memory is memory-mapped and does not require dedicated DMA handling.

Remove extended mode NORSRAM_EXTENDED_TypeDef

Bank 1 is selected directly without requiring explicit , the instance will be used to sub-banks.
