Script stubbing features ¶

1. Overview ¶

In addition to its detection capabilities, the hal1_detection script offers a robust stubbing mechanism for HAL1 elements within user code. The stubbing feature encompasses a wide range of constructs, including function calls (direct, nested, or conditional), structures (such as typedefs, function arguments, or initializations), enumerations (user-defined or used within function calls), constants (as arguments or in variable assignments), and macros. The following sections will provide a comprehensive overview of stubbing configuration , supported patterns and corresponding resolution techniques.

Note

By stubbing, we refer to the isolation and exclusion of code segments related to HAL1 API, such as function calls, variable declarations, and other related components.

Example

Original Code

Stubbed Code 

HAL_ADC_Start();

#ifdef TO_DO_RESOLVE_STUB
HAL_ADC_Start();
#endif /* TO_DO_RESOLVE_STUB */

2.1 Stubbing configurability ¶

Users have the flexibility to customize the stubbing compilation flag to suit their specific requirements. This can be achieved by overriding the default value of StubbingCompilationFlag in the hal1_detection_config.py file, or by modifying it directly through the interactive menu.

2.2 Warning message configurability ¶

Users have the ability to customize the injected warning log messages according to their preferences. To achieve this, modifications can be made to the hal1_detection_config.py file.

Note that the UseWarningMessage must be set to True to enable customization of the configuration, otherwise, the customized settings will be ignored.

3. Usage ¶

3.1 Detection and stubbing usage ¶

script usage [stubbing mode] ¶

Description

Purpose

Analyze the source files to identify and, eventually, modify them by stubbing the selected modules.

A detailed log file will be generated

Syntax

One of the following commands can be used 

# Using the Python script
# Compatible with bash and Windows console
python hal1_detection.py -d stub -psrc PATH -m all|module1 module2 ...

# Using the executable on bash
./hal1_detection.exe -d stub -psrc PATH -m all|module1 module2 ...

# Using the executable on Windows console
hal1_detection.exe -d stub -psrc PATH -m all|module1 module2 ...

Required Arguments

  • -psrc PATH : Path to the source file or directory.

  • -m : Specify modules ( all or space-separated list).

  • -d stub : Detects, stubs, and may modify user source files, generating a log file.

3.2 Examples ¶

Examples 

# On windows console
# Detect and stub all HAL1 APIs in .\src
hal1_detection.exe -d stub  -psrc .\src -m all

# On bash env use
./hal1_detection.exe -d stub  -psrc ./src -m all

# On windows console
# Detect and stub only 'gpio' and 'uart' APIs in .\src
hal1_detection.exe -d stub -psrc .\src -m gpio uart

# On bash env use
./hal1_detection.exe -d stub -psrc ./src -m gpio uart

# On windows console
# Detect and stub specific HAL1 APIs in a single file
hal1_detection.exe -d stub -psrc .\src\main.c -m spi i2c

# On bash env use
./hal1_detection.exe -d stub -psrc ./src/main.c -m spi i2c

4.2 Resolve stubbing patterns ¶

Once HAL1 Code have been stubbed , we recommend the following sequence to resolve pattern .

  1. Replace HAL1 API by HAL2 equivalent according to file log links .

  2. Comment the #warning , #ifdef and #endif compilation directives .

  3. Carry on with this approach until the whole applicative file is solved .

  4. Delete the commented-out compilation directives.

Tricky cases : ¶

do..while ¶

Initial user code : 

do
{
  HAL1_PPP_Function1(&hppp, ...);
  HAL1_PPP_Function2(&hppp, ...);
} while (Condition = HAL1_func_return_value);

Stubbed user code : 

#ifdef TO_DO_RESOLVE_STUB
do
#endif /* TO_DO_RESOLVE_STUB */
{
#ifdef TO_DO_RESOLVE_STUB
  HAL1_PPP_Function1(&hppp, ...);
#endif /* TO_DO_RESOLVE_STUB */
#ifdef TO_DO_RESOLVE_STUB
  HAL1_PPP_Function2(&hppp, ...);
#endif /* TO_DO_RESOLVE_STUB */
}
#ifdef TO_DO_RESOLVE_STUB
while (Condition = HAL1_func_return_value);
#endif /* TO_DO_RESOLVE_STUB */

Resolve the do..while statement and comment the #ifdef TO_DO_RESOLVE_STUB and the #endif TO_DO_RESOLVE_STUB . 

//#ifdef TO_DO_RESOLVE_STUB
do
//#endif /* TO_DO_RESOLVE_STUB */
{
 ....
}
//#ifdef TO_DO_RESOLVE_STUB
while (Condition = HAL2_func_return_value);
//#endif /* TO_DO_RESOLVE_STUB */

You can carry now with solving the APIs inside the do..while . 

{
//#ifdef TO_DO_RESOLVE_STUB
  HAL2_PPP_Function1(&hppp, ...);
//#endif /* TO_DO_RESOLVE_STUB */
//#ifdef TO_DO_RESOLVE_STUB
  HAL2_PPP_Function2(&hppp, ...);
//#endif /* TO_DO_RESOLVE_STUB */
}

Finally remove the comments when completing the whole applicative file . 

do
{
  HAL2_PPP_Function1(&hppp, ...);
  HAL2_PPP_Function2(&hppp, ...);
}
while (Condition = HAL2_func_return_value);

switch (Selector = HAL1 func ret value)
