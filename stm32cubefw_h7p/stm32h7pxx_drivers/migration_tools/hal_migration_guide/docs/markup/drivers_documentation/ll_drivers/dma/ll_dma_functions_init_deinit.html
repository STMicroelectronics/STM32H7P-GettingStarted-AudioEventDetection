LL_DMA_Init and LL_DMA_DeInit APIs migration ¶

The LL initialization and de-initialization functions previously available in the stm32tnxx_ll_dma.c files within HAL1 are no longer present in HAL2. In HAL2, all LL C files ( stm32tnxx_ll_dma.c ) have been removed, leaving only the LL header files ( stm32tnxx_ll_dma.h ) that contain static inline functions.

If users need to initialize or de-initialize DMA using the LL layer, they have to:

Replace manually the initialization and de-initialization functions : Replace the LL_DMA_Init and LL_DMA_DeInit functions manually with equivalent sequences using the static inline functions provided in the stm32tnxx_ll_dma.h file, tailored to their specific configuration and requirements.

This approach ensures that the initialization and de-initialization sequences are precisely addressing the given use case based on the LL static inline functions provided in the stm32tnxx_ll_dma.h header file. The sequences offer improved footprint optimization compared to the previous LL initialization functions found in stm32tnxx_ll_dma.c .

LL_DMA_DeInit() API migration ¶

According to the used DMA channel, Implement the precise calls to LL_AHB2_GRP1_ForceReset() and LL_AHB2_GRP1_ReleaseReset

Example: The application is using GPDMA1 instance

Comparison of HAL1 and HAL2 ¶

HAL2 

/* DeInit all GPDMA1 channels */

LL_DMA_DeInit(GPDMA1, LL_DMA_CHANNEL_ALL);

LL_AHB2_GRP1_ForceReset(LL_AHB1_GRP1_PERIPH_GPDMA1);
LL_AHB2_GRP1_ReleaseReset(LL_AHB1_GRP1_PERIPH_GPDMA1);
