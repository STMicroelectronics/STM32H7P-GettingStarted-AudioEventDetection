HAL FMAC constants migration ¶

This section provides information about the HAL FMAC constants migration .

HAL FMAC Buffer Access Modes Constants ¶

HAL1

HAL2 

#define FMAC_BUFFER_ACCESS_DMA
#define FMAC_BUFFER_ACCESS_IT
#define FMAC_BUFFER_ACCESS_POLLING
#define FMAC_BUFFER_ACCESS_NONE

Removed: in HAL2 we use HAL_FMAC_WriteX1(), HAL_FMAC_WriteX1_IT(), HAL_FMAC_WriteX1_DMA(), HAL_FMAC_WriteX1_DMA_Opt()
         to manage the input data and HAL_FMAC_ReadY, HAL_FMAC_ReadY_IT, HAL_FMAC_ReadY_DMA, HAL_FMAC_ReadY_DMA_Opt()
         to manage the output data, and if we want another peripheral to handle the input or output data, we do not simply call
         read or write.

Note

In HAL2 we have also HAL_FMAC_LockX1WriteAccessForExternPeriph and HAL_FMAC_UnlockX1WriteAccessForExternPeriph

to protect the FMAC driver against accidental calls to the WriteX1 APIs in case of input data managed by an external peripheral and we have HAL_FMAC_LockYReadAccessForExternPeriph and HAL_FMAC_UnlockYReadAccessForExternPeriph to protect the FMAC driver against accidental calls to the ReadY APIs in case output data managed by an external peripheral.

Related use case : FIR or IIR Interrupt input/X1, DMA output/Y

Related use case : FIR or IIR PERIPH ADC input/X1, DMA output/Y

HAL FMAC Status Flags Constants ¶

HAL1

HAL2 

/* */

#define FMAC_FLAG_OVFL
#define FMAC_FLAG_SAT
#define FMAC_FLAG_UNFL
#define FMAC_FLAG_X1FULL
#define FMAC_FLAG_YEMPTY

Removed: these defines in HAL1 were used with __HAL_FMAC_GET_FLAG to check whether the specified FMAC status flag is set or not,
        in HAL2 all FMAC flag definitions are removed and use instead the following static inlines:
LL_FMAC_IsActiveFlag_OVFL to read overflow error flag.
LL_FMAC_IsActiveFlag_SAT to read saturation error flag.
LL_FMAC_IsActiveFlag_UNFL to read underflow error flag.
LL_FMAC_IsActiveFlag_X1FULL to read X1 buffer full flag.
LL_FMAC_IsActiveFlag_YEMPTY to read Y buffer empty flag.

HAL FMAC Function Modes Constants ¶

HAL1

HAL2 

/* */

#define FMAC_FUNC_LOAD_X1
#define FMAC_FUNC_LOAD_X2
#define FMAC_FUNC_LOAD_Y

Removed: as they have been specified in the filter parameter within the FMAC_FilterConfigTypeDef structure in HAL1,
in HAL2 we use:
- HAL_FMAC_StartFilterFIR to start the FIR filtering
- HAL_FMAC_StartFilterIIR to start the IIR filtering

- HAL_FMAC_PreloadX1 to preload X2
- HAL_FMAC_PreloadX1 and HAL_FMAC_PreloadY_DMA to preload Yin polling and DMA modes

Related concept : All public macros related to hardware (HW) are removed, and equivalent services added to the LL layer.

HAL FMAC Threshold Values Constants ¶

In HAL1, the threshold values were specified using the InputThreshold and OutputThreshold fields within the FMAC_FilterConfigTypeDef structure. In HAL2, configuration is done via HAL_FMAC_SetX1FullWatermark for the FMAC X1 full watermark threshold, and HAL_FMAC_SetYEmptyWatermark for the FMAC Y empty watermark threshold. The threshold values are defined by the hal_fmac_watermark_threshold_t enumeration

HAL1

HAL2 

/* */

#define FMAC_THRESHOLD_1
#define FMAC_THRESHOLD_2
#define FMAC_THRESHOLD_4
#define FMAC_THRESHOLD_8
#define FMAC_THRESHOLD_NO_VALUE

        typedef enum
{
  HAL_FMAC_WATERMARK_THRESHOLD_1
  HAL_FMAC_WATERMARK_THRESHOLD_2
  HAL_FMAC_WATERMARK_THRESHOLD_4
  HAL_FMAC_WATERMARK_THRESHOLD_8
} hal_fmac_watermark_threshold_t;
